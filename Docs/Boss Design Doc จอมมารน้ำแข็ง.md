# Boss Design Doc: จอมมารน้ำแข็ง

Oct 14, 2026 · @Pete

## ภาพรวมและคอนเซปต์

ไครออส (Kryos) จอมมารน้ำแข็ง คือบอสใหญ่ของโซนน้ำแข็ง สู้ 3 เฟส ใช้เวลาประมาณ 4–6 นาที บอสชนะด้วยการวางแผน ไม่ใช่พลังดิบ: คุมพื้นที่ แยกผู้เล่นออกจากกัน แล้วลงมือกับคนที่พลาด

- **บุคลิก:** เยือกเย็น หยิ่ง มองผู้เล่นเป็นของเล่น ไม่วิ่งไล่ แต่เทเลพอร์ตไปยังจุดที่ได้เปรียบ
- **บทบาทในเกม:** บอสท้ายโซน ทดสอบการหลบ telegraph และการช่วยเพื่อนใน co-op
- **ความรู้สึกที่ต้องการ:** ช่วงแรกผู้เล่นรู้สึกว่าโดนอ่านทาง ช่วงท้ายรู้สึกว่าชนะเพราะทีมประสานกันได้
- **ลูกน้อง:** Ice Golem ผู้พิทักษ์ที่บอสเรียกออกมาเป็นโล่
- **มุมกล้อง:** top-down ทุกการตัดสินใจด้านภาพต้องอ่านออกจากด้านบน

## Visual design และสเปกโมเดล

บอสสูงโปร่ง ตัวสีเข้มตัดกับผลึกฟ้าสว่าง เพื่อไม่ให้จมพื้นหิมะ และจุดเด่นทุกอย่างต้องเห็นจากด้านบน

- **มงกุฎและเขา:** ใหญ่ แผ่ออกด้านข้าง เป็นสิ่งแรกที่เห็นจากมุมบน
- **เสื้อคลุม:** ยาวคลุมขา ชายเสื้อแผ่ออก บอสลอยหรือไถลแทนการเดิน
- **แกนผลึกกลางหลัง:** จุดอ่อน เรืองแสง เปิดออกช่วงท่าไม้ตาย
- **ผลึกลอย 3 ชิ้น:** หมุนรอบตัว ใช้บอกเฟสและเป็นกระสุน แตกทีละชิ้นตามเฟส
- **คทาผลึก:** ถือมือขวา บอกทิศที่บอสกำลังร่าย
- **พาเลตต์:** น้ำเงินเข้ม ม่วงเข้ม ดำ กับฟ้าสว่างเป็น accent ห้ามใช้ขาวเป็นสีหลัก

| ชิ้นงาน | สเปก |
| --- | --- |
| ตัวบอส | 1,500–4,000 quads (3,000–8,000 tris) |
| คทา | โมเดลแยก ผูกกับกระดูกมือขวา |
| ผลึกลอย | โมเดลแยก ประมาณ 50–150 quads ต่อชิ้น หมุนด้วยโค้ด |

| Pivot / ทิศ | pivot ที่ใต้ชายเสื้อ หันหน้าแกน +Z |
| Shading | flat, Smoothing Angle = 0 |

## ค่าสถานะและเฟส

ตั้ง HP จากเวลาสู้ที่ต้องการ (4–6 นาที) แทนการเดาตัวเลข ค่าทั้งหมดในเอกสารนี้เป็นค่าตั้งต้นสำหรับจูน ดาเมจคิดเป็น % ของ HP สูงสุดผู้เล่น เพื่อไม่ผูกกับระบบสเตตัสที่ยังเปลี่ยนได้

```latex
HP_{boss} = DPS_{player} \times 300 \times \big(1 + 0.6 \times (N_{players} - 1)\big)
```

300 คือเป้าเวลาสู้ 5 นาที (วินาที) ส่วน 0.6 คือ HP ที่เพิ่มต่อผู้เล่นหนึ่งคน ไม่เพิ่มเต็ม 1.0 เพราะผู้เล่นต้องเสียเวลาช่วยเพื่อน

| ค่า | ตั้งต้น |
| --- | --- |
| ความเร็วเคลื่อนที่ | 70% ของผู้เล่น (ช้ากว่า ใช้เทเลพอร์ตแทน) |
| ดาเมจท่าทั่วไป | 10–25% HP ผู้เล่น |
| ดาเมจท่าไม้ตาย | 75% HP ผู้เล่น (เฟส 3: ตายทันที) |
| Stagger | สะสมดาเมจ 8% HP บอสภายใน 4 วินาที บอสชะงัก 2 วินาที |
| ช่วงพักระหว่างท่า | 1.5 วิ (เฟส 1) → 1.0 วิ (เฟส 2) → 0.7 วิ (เฟส 3) |

| เฟส | ช่วง HP | ผลึกลอย | สิ่งที่เพิ่มเข้ามา |
| --- | --- | --- | --- |
| 1 สังเกตการณ์ | 100–60% | 3 ชิ้น | ท่าพื้นฐาน, เทเลพอร์ต, Golem 1 ตัว |
| 2 ไล่ล่า | 60–25% | 2 ชิ้น | กำแพงน้ำแข็ง, Frozen Judgment, Golem 2 ตัว |
| 3 ศูนย์สัมบูรณ์ | 25–0% | 1 ชิ้น | Absolute Zero, ท่าไม้ตายประหารได้, ใช้ท่าเร็วขึ้น |

ทุกครั้งที่เปลี่ยนเฟส บอสอมตะ 3 วินาที เล่นท่าเปลี่ยนเฟส ผลึกลอยแตก 1 ชิ้น และล้างสถานะ Chill ของผู้เล่นทุกคน

## ห้องบอส

ห้องบัลลังก์น้ำแข็งทรงวงกลม ขนาดประมาณ 2 หน้าจอ ให้กล้องตามผู้เล่นได้แต่บอสไม่หลุดจอนาน

- **พื้น:** หินสีเข้มมีหิมะบางๆ เพื่อให้ telegraph สีฟ้าบนพื้นเห็นชัด
- **เสาน้ำแข็ง 4 ต้น:** ใช้หลบกระสุน ทำลายได้ด้วยท่า Absolute Zero ในเฟส 3 ทำให้ห้องโล่งขึ้นตามเฟส
- **จุดเทเลพอร์ต 5 จุด:** กลางห้อง + 4 มุม มีวงเวทย์บนพื้นให้ผู้เล่นเดาได้ว่าบอสจะไปโผล่ที่ไหน
- **บัลลังก์:** อยู่ขอบบนของห้อง เป็นจุดที่บอสนั่งตอนเปิดตัว
- **ทางเข้า:** ปิดด้วยกำแพงน้ำแข็งเมื่อเริ่มสู้ เปิดเมื่อบอสตาย

## ท่าไม้ตาย: Frozen Judgment

ท่านี้ยาวประมาณ 6 วินาที มีทางรอด 3 จุด: หลบวงแรก, เพื่อนตีน้ำแข็งช่วย, และทีมขัดจังหวะช่วงประหาร ผู้เล่นที่โดนประหารต้องรู้สึกว่าพลาดเองหรือทีมช่วยไม่ทัน ไม่ใช่โดนเกมแกล้ง

1. **0.0–1.5 วิ ล็อกเป้า:** บอสชูคทา วงน้ำแข็งก่อตัวใต้เท้าเป้าหมาย 1 คน ถ้าหลบพ้น ท่าทั้งหมดยกเลิก บอสเสียจังหวะ 1 วินาที
2. **1.5 วิ แช่แข็ง:** เป้าหมายกลายเป็นก้อนน้ำแข็ง ขยับไม่ได้ กดปุ่มรัวเพื่อลดเวลาแช่ (กดครั้งละ -0.15 วิ)
3. **1.5–2.0 วิ เทเลพอร์ต:** บอสหายแล้วโผล่ด้านหลังเหยื่อ
4. **2.0–3.0 วิ คลื่นน้ำแข็ง:** วงขยายออกจากตัวบอส ผู้เล่นอื่นที่โดนจะถูกแช่แข็ง 2.5 วิ หลบได้ด้วยการ dash หรือหลบหลังเสา
5. **3.0–6.0 วิ ประหาร:** บอสกำมือ น้ำแข็งรอบเหยื่อหนาขึ้นจนแตก แกนผลึกกลางหลังบอสเปิดออก
   - ทีมทำดาเมจที่แกนถึง 5% HP บอส: บอสปล่อยเหยื่อและชะงัก 3 วินาที (ดาเมจที่แกน x2 ช่วงนี้)
   - เพื่อนตีน้ำแข็งที่ขังเหยื่อ 4 ครั้ง: เหยื่อหลุด ไม่โดนดาเมจ
   - ไม่มีใครขัด: น้ำแข็งแตก เหยื่อโดนดาเมจ 75% (เฟส 3: ตาย)

**กฎเพิ่มเติม**

- ใช้ได้ 1 ครั้งต่อเฟส ห้ามเลือกเป้าคนเดิมติดกัน
- เลือกเป้าหมายคนที่อยู่ห่างจากเพื่อนมากที่สุด (คนที่แยกตัว)
- เล่นคนเดียว: ข้ามขั้นที่ 4 และเวลาแช่ลดลงเร็วขึ้นสองเท่าตอนกดรัว
- ท่าประหารใช้แบบแช่แข็งจนแตก ไม่ใช้ paired animation จึงไม่ต้องจัดตำแหน่งผู้เล่นให้ตรงกับมือบอส

## สถานะผิดปกติและลูกน้อง

**Chill (สะสมได้ 3 ชั้น):** ช้าลง 15% ต่อชั้น ครบ 3 ชั้นกลายเป็น Frozen ชั้นลดลง 1 ทุก 3 วินาทีถ้าไม่โดนเพิ่ม แสดงเป็นเกล็ดน้ำแข็งเกาะตัวผู้เล่น ให้เพื่อนเห็นว่าใครใกล้โดนแช่

**Frozen:** ขยับไม่ได้ 2 วินาที (กดรัวลดได้) ระหว่างแช่รับดาเมจลดลง 30% เพราะน้ำแข็งเป็นเกราะ หลุดแล้วอมตะต่อ Frozen 4 วินาที กันโดนแช่ซ้ำติดกัน

**Ice Golem**

| ค่า | ตั้งต้น |
| --- | --- |
| HP | 8% ของ HP บอส |
| ความเร็ว | 60% ของผู้เล่น |
| ท่า | ทุบพื้นเป็นวง 1.0 วิ telegraph, ดาเมจ 20% |
| พฤติกรรม | ยืนขวางระหว่างผู้เล่นที่ใกล้ที่สุดกับบอส |
| ตาย | แตกเป็นเศษน้ำแข็ง ทิ้งพื้นลื่น 5 วิ |
| จำนวนสูงสุด | เฟส 1: 1 ตัว, เฟส 2–3: 2 ตัว |

โมเดล Golem ใช้ prompt ชุดแรกที่คุยกันไว้ (ร่างหินกับผลึก ไหล่กว้าง) แต่ย่อขนาดให้เล็กกว่าบอส

**VFX**

- Telegraph บนพื้น: วงกลม พัด เส้นตรง (ใช้ decal หรือ projector สีฟ้า ขอบสว่างขึ้นเมื่อใกล้ถึงเวลา)
- กระสุน Frost Bolt, เส้นทางผลึกลอย, กำแพงน้ำแข็งงอกขึ้นและแตก

- แกนผลึกกลางหลังเรืองแสงแรงขึ้นช่วงเปิด, hit flash, ออร่าหมอกเย็น

**Audio**

- เสียงพูดของบอส: เปิดฉาก, เปลี่ยนเฟส, ใช้ท่าไม้ตาย, ตาย

- เพลงบอส แยก 3 layer ตามเฟส

## การ implement ใน Unity

แยก logic ออกจากข้อมูล: ค่าทุกท่าอยู่ใน ScriptableObject ปรับ balance ได้โดยไม่แก้โค้ด และให้ host หรือ server เป็นเจ้าของ AI ของบอสเพียงที่เดียว

| Component / Asset | หน้าที่ |
| --- | --- |
| `BossController` | state machine หลัก เลือกท่า สั่ง Animator |
| `BossHealth` | HP, stagger, อมตะช่วงเปลี่ยนเฟส, event `OnPhaseChanged` |
| `BossPhaseData` (ScriptableObject) | ช่วง HP, รายการท่าที่ใช้ได้, ช่วงพักระหว่างท่า |
| `BossAttackData` (ScriptableObject) | ดาเมจ, ระยะ, telegraph, cooldown, น้ำหนักการสุ่ม, prefab ของ VFX |
| `BossAttack` (abstract) + คลาสย่อยต่อท่า | ลำดับการทำงานของแต่ละท่าแบบ coroutine |
| `TelegraphSpawner` | สร้าง decal บนพื้นตามรูปทรงและเวลา |
| `StatusEffects` (บนผู้เล่น) | Chill, Frozen, การกดรัว, อมตะหลังหลุด |
| `OrbitingCrystals` | หมุนผลึกรอบตัว ปล่อยเป็นกระสุน แตกตามเฟส |
| `TargetSelector` | เลือกเป้าตามกฎของแต่ละท่า |
| `ObjectPool` | กระสุน, VFX, Golem |
| `BossHealthBarUI` | ชื่อบอส, แถบ HP, เส้นแบ่งเฟส |

**การเลือกท่า**

1. กรองท่าที่ใช้ได้ในเฟสปัจจุบันและ cooldown หมดแล้ว
2. กรองตามระยะถึงเป้าหมาย
3. สุ่มตามน้ำหนัก และลดน้ำหนักท่าที่เพิ่งใช้ เพื่อไม่ให้ซ้ำติดกัน

**Animator**

- ใช้ trigger ต่อท่า ไม่ใช้ root motion (บอสเคลื่อนที่ด้วยโค้ด)
- Animation Event: `OnAttackHit`, `OnCastRelease`, `OnBlinkVanish`
- เคลื่อนที่ด้วย NavMeshAgent ทั้งบอสและ Golem

**Co-op**

- Host หรือ server รัน `BossController` คนเดียว ฝั่ง client แค่แสดงผล
- Sync: HP, state ปัจจุบัน, ท่าที่กำลังใช้ + เป้าหมาย + timestamp เริ่ม telegraph
- Client เล่น telegraph และ VFX เองจาก timestamp เพื่อลดข้อมูลที่ต้องส่ง
- การกดรัวตอน Frozen คำนวณที่ client ของเหยื่อแล้วส่งผลรวมให้ host

## การจูน, playtest และคำถามที่ยังเปิด

ทำต้นแบบด้วย capsule ก่อนเสมอ ให้ AI และท่าโจมตีสนุกก่อน แล้วค่อยใส่โมเดล animation และ VFX

**ค่าที่ต้องจูนบ่อยที่สุด:** HP ต่อจำนวนผู้เล่น, เวลา telegraph, ช่วงพักระหว่างท่า, เกณฑ์ stagger, ดาเมจที่ต้องใช้ขัดท่าไม้ตาย

**Playtest checklist**

- [ ] ผู้เล่นใหม่อ่าน telegraph ทุกท่าออกภายในการเล่น 2 รอบ
- [ ] เวลาสู้จริงอยู่ในช่วง 4–6 นาที ทั้งเล่น 1 คนและเต็มทีม
- [ ] ไม่มีจังหวะที่ผู้เล่นทุกคนโดนแช่พร้อมกันโดยไม่มีทางหลบ
- [ ] ผู้เล่นที่โดน Frozen Judgment บอกได้ว่าพลาดตรงไหน
- [ ] ทีมขัดท่าไม้ตายสำเร็จได้อย่างน้อยครึ่งหนึ่งของครั้งที่พยายาม
- [ ] บอสไม่ใช้ท่าเดิมติดกันเกิน 2 ครั้ง
- [ ] มองเห็นบอสชัดบนพื้นหิมะทุกจุดของห้อง
- [ ] Client กับ host เห็น telegraph ตรงกัน (ทดสอบที่ ping 150 ms)

**คำถามที่ยังเปิด**

- เกมมีปุ่ม dash หรือ i-frame ไหม (ถ้าไม่มี ต้องเพิ่มเวลา telegraph)
- จำนวนผู้เล่นสูงสุดต่อทีม
- ผู้เล่นที่ตายฟื้นได้ระหว่างสู้บอสไหม
- ใช้ระบบ networking ตัวไหน
