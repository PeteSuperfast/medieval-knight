# Phase 7 — design: clash / parry / ท่าหนักของศัตรู
> ไฟล์นี้ = ข้อ 1–3 (ต่อสู้) | ข้อ 4–6 (เลขดาเมจ, กล้อง, แผนที่ M) อยู่ใน `design-ui.md`
> เสาหลัก 1 "ต่อสู้รู้สึกดี" | ข้อความในเกมเป็นอังกฤษ | อ้างจาก Knight.TakeDamage / Minotaur / Slime ปัจจุบัน

## 1. เป้าหมายผู้เล่น
- ฟันสวนจังหวะที่ศัตรูฟาด = ชน (CLASH) ไม่เจ็บทั้งคู่; ยกโล่ทันก่อนโดนนิดเดียว = PARRY ศัตรูเปิดช่องให้สวน
- เห็นสีเตือนก็รู้เลยว่าท่านี้ "ชน/ปัดไม่ได้" ต้อง dash หรือหลบ — อ่านท่าได้ ไม่งง

## 2. สิ่งที่ต้องมี (ไม่มีหน้าจอใหม่)
| # | องค์ประกอบ | หมายเหตุ |
|---|---|---|
| a | Popup "CLASH" / "PARRY!" / "HEAVY" ลอยเหนือหัว | ใช้ `Hud.Popup` เดิม |
| b | ประกาย + วงแหวน ณ จุดกึ่งกลางผู้เล่น-ศัตรู | `Fx.Burst/Ring` เดิม |
| c | โล่แฟลชฟ้าอ่อน 0.2 วิ ตอนยกโล่ (= หน้าต่าง parry ยังเปิด) | บอกผู้เล่นว่ายัง parry ได้ |
| d | แสงเตือนท่าหนักของศัตรู (เรือง/วง/"!") | ข้อ 5 |
| e | สีพื้นเตือนท่าเบา = ทอง (ปัดได้) / ท่าหนัก = แดง (ปัดไม่ได้) | ข้อ 5 |

## 3. นิยาม CLASH (เล่นแล้วรู้เรื่อง)
เกิดเมื่อ "ศัตรูฟาด/กระโดดชน" ณ ขณะที่จะโดนผู้เล่น และครบทุกข้อ:
1. **จังหวะ**: ผู้เล่นอยู่ในช่วง "ดาบกำลังฟาด" ของท่าเบา (ช่วง strike ขยายก่อน-หลังอย่างละ 0.1 วิ ≈ หน้าต่าง 0.25–0.35 วิ ที่ผู้เล่นรู้สึก) — ท่า Heavy Strike ไม่นับ
2. **ทิศตรงข้าม**: ศัตรูอยู่ในครึ่งหน้าผู้เล่น (±60° จากทิศหัน) และห่าง ≤ 5.5 ม. = เขาฟาดเข้าหาเรา เราฟาดเข้าหาเขา
3. ท่าศัตรูต้องเป็นท่าเบา (ข้อ 5); หนึ่งฟันของผู้เล่นชนได้ 1 ครั้ง
4. ผู้เล่นกำลังยกโล่ = ไม่ใช่ clash (เป็นบล็อก/parry)

ผล (ทั้งคู่ไม่เสียดาเมจ ไม่เสีย armor):
| ฝั่ง | ผล |
|---|---|
| ผู้เล่น | ถอย 1.5 ม. ใน 0.15 วิ ฟันต่อได้ตามปกติ ไม่ยกเลิกคอมโบ |
| สไลม์ | กระเด็น 3 ม. + หยุด 0.3 วิ (ฟันของผู้เล่นรอบนี้ไม่ทำดาเมจตัวที่ชน ตัวอื่นในวงยังโดน) |
| Minotaur Sweep | ไม่กระเด็น (บอสต้านแรงผลัก) แต่ท่าถูกขัด → Recover 0.5 วิ ไม่สตัน |
| หุ่นฟาง | ไม่โจมตี → ไม่มี clash (ใช้ hook debug ในเทสต์) |

Feedback: ประกายแฉกสีขาว-ทอง #F5C25A 14 อนุภาค + วง 1.2 ม. ที่จุดกึ่งกลาง, popup `CLASH` ขาว 28, เสียง `Snd.Clash` pitch ต่ำ 0.9 vol 1.0 (ให้ "หนัก" กว่าบล็อก), hit-stop 0.08 วิ (แช่ท่าผู้เล่น+ศัตรู ห้ามใช้ timeScale ออนไลน์), กล้องสั่ง 0.12 / 0.15 วิ

## 4. นิยาม PARRY
- **หน้าต่าง 0.2 วิ นับจากกดคลิกขวา (เริ่มยกโล่)**: ถ้าดาเมจเบาเข้าจากด้านหน้า (มุมโล่ 75° เดิม) ภายใน 0.2 วิ นั้น = parry; ยกโล่ค้างไว้แล้วโดนทีหลัง = บล็อกปกติ (80% เดิม)
- กันสแปม: กดใหม่ภายใน 0.5 วิ หลังกดครั้งก่อน = ไม่มีหน้าต่าง parry (บล็อกปกติยังได้)
- ท่าหนักของศัตรู: ไม่ parry ได้ → บล็อกปกติ + popup `HEAVY` แดง (สอนผู้เล่นว่าทำไมไม่ parry)

| | บล็อกปกติ (เดิม) | PARRY |
|---|---|---|
| ดาเมจ/armor | ลด 80% | 0 ไม่เสีย armor |
| ฝ่ายโจมตี | ไม่เกิดอะไร | กระเด็น 4 ม. + สตัน 0.6 วิ (บอส: ไม่กระเด็น สตัน 0.5 วิ ตาม stunResist) |
| ผู้เล่น | ถอย 35% ของแรง | ไม่ถอย |
| ประกาย | เหลือง 12 อนุภาค (เดิม) | ฟ้าขาว #CFE8FF 18 อนุภาค + วง 1.8 ม. |
| popup | `BLOCK` เหลือง 26 | `PARRY!` ฟ้าอ่อน 32 |
| เสียง | Clash pitch 1.0 | Clash pitch 1.35 vol 1.0 (สูง ใส) |
| hit-stop / กล้อง | – / 0.08 | 0.10 วิ / 0.16 สั้น 0.12 วิ |

หมายเหตุ: สตันที่ได้ = ช่องโอกาสสวน (ไม่เพิ่มโบนัสดาเมจ/คริ ใน phase นี้)

## 9. ต่างจาก requirement / คำถามให้ปูส้มตัดสิน
1. **สไลม์แดง = หนัก** (ผมเสนอ) ถ้าแพ็คแดงเยอะ clash/parry ใช้ได้น้อยลง — ทางเลือก: สไลม์ทุกสีเบา, หนักเฉพาะบอส
2. เปลี่ยนสีพื้นเตือน Sweep จากแดง → ทอง (แตะโค้ดบอสเล็กน้อย) เพื่อแยกเบา/หนักด้วยสีเดียวกันทั้งเกม
3. เพิ่ม "กันสแปม parry 0.5 วิ" และ "โล่แฟลช 0.2 วิ" — ไม่อยู่ใน requirement เดิม (ถ้าไม่เอา: ตัดได้ ไม่กระทบอย่างอื่น)
4. Clash นิยามด้วย "ช่วงฟาดผู้เล่น ± 0.1 วิ" ไม่ใช่เทียบ hitbox ศัตรู เพราะศัตรูโจมตีเป็นเหตุการณ์ชั่วขณะ (ไม่มี hitbox ค้าง); architect ปรับตัวเลขได้ถ้าเล่นแล้วแคบ/กว้างไป
5. เสียงใช้ `Snd.Clash` ตัวเดียวแยกด้วย pitch — ถ้าเล่นแล้วแยกไม่ออก ค่อยเสนอเสียงใหม่ (backlog)
